## `01` — About Me

Hey! I'm **Udhay**, a developer and builder interested in the intersection of AI, software engineering, and developer infrastructure.

I enjoy taking ideas from a rough concept to a working product — designing systems, writing code, experimenting with new technologies, and figuring out how things work under the hood.

I'm particularly interested in building tools that make developers more productive, exploring how AI agents can collaborate on complex tasks, and creating software that feels useful beyond a demo.

- 🤖 **AI & Agents** — Multi-agent systems, intelligent workflows, and AI-powered applications.
- 🛠️ **Developer Infrastructure** — MCP servers, code intelligence, automation, and developer tooling.
- 🧪 **Experiments** — Game-playing AI, programming languages, simulations, and unconventional ideas.
- 🚀 **Product Building** — Turning ideas into usable products, iterating quickly, and learning through shipping.
- 🧠 **Currently learning** — Neural networks, AI systems, algorithms, and deeper software engineering fundamentals.

🌐 **Explore my work:** [udhaycodes.space](https://udhaycodes.space)

> I don't just want to use the tools developers have. I want to understand how they work and build better ones.

## `05` — What I'm Exploring Right Now


**Current areas of exploration:**

- 🧠 **Neural networks:** Understanding the mechanics behind networks, training, policies, and learning through experiments such as Mario AI.
- 🕸️ **AI agent systems:** Building workflows where agents can plan, use tools, coordinate tasks, and work with real software projects.
- 🔌 **MCP ecosystem:** Exploring how AI applications can connect to tools, data sources, and developer environments through standardized interfaces.
- 🌳 **Code intelligence:** Building structured representations of codebases so AI systems can reason about projects with useful context.
- 🧪 **Programming language design:** Exploring parsers, grammars, abstract syntax trees, and the design of my own language, Nova.
- ⚙️ **Systems engineering:** Learning through real implementations, debugging, performance constraints, and practical architecture decisions.

I learn best by building something, hitting a wall, figuring out why, and trying again.
